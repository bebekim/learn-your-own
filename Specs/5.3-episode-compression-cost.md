# 5.3 — Episode Compression × Cost: Measuring Waste

**State:** implemented
**Layer:** 5 (scoring)
**Dependencies:** 5 (scoring direction), 4.6 (measurement), 5.2 (cost attribution).

## Problem

Per-prompt statistics have an independence violation: a debugging episode of 8 prompts
about the same failing test is 1 observation echoed 8 times, not 8. Counting echoes
inflates n and skews every distribution (the 74% `follow_up` mass). And now that cost
is attributed per turn (5.2), the same redundancy has a **price**: without
compression we know the total burn but not the waste — how many tokens re-trod an
intent that was already paid for.

The unit of waste is the episode, not the prompt. Compressing repeated noise is what
turns "spend by turn" into "cost of driving the agent ineffectively."

## Design

### Episode compression (read-side)

Group consecutive user prompts within a session into episodes by continuity:

- A prompt joins the current episode when its summary token-overlap (Jaccard) with
  the previous user prompt is ≥ 0.5 — the same documented prior as retry detection
  (spec 5, R3). No new hand parameters.
- **Work-arc continuation (added after lens comparison on real data):** a short
  prompt (≤ 5 tokens) following a completed turn (an assistant prompt row exists
  between the two user prompts) also continues the episode, even with zero token
  overlap. Continuations signal by reference ("proceed", "do that", "what's next"),
  not by repetition — similarity alone is blind to them. Structural only: length +
  turn position, no content patterns. The 5-token threshold joins the documented
  priors under spec 5 R3.
- The first prompt of a session (index 0) always starts episode 1.
- An episode's dominant kind is the argmax of summed log-LR evidence across member
  prompts.

### Cost rollup

Episode cost = sum of `estimated_cost` over `model_calls` whose `turn_id` belongs to
a member prompt's turn.

### Waste metrics

- **compressionRatio** = user prompts / episodes. The noise level of the corpus.
- **echoSpend** = cost of turns belonging to non-first prompts within episodes.
  Candidate waste: spend re-treading an intent already underway. (Not all echoes are
  waste — legitimate follow-ups exist; this is the upper-bound candidate number.)
- **retrySpend** = cost of turns whose prompt is a retry (existing retry detector).
  The unambiguous waste subset.
- Per-episode: cost, member count, dominant kind.

## Interface

`src/measurement/episodes.ts`:

```typescript
export function buildPromptEpisodes(kernel: LearningKernel): PromptEpisode[];
```

New `episodes` section in `prompt-kind-report`:

```
episodes: {
  count, compressionRatio,
  echoSpend, retrySpend,
  byKind: Record<kind, number>,      // dominant-kind distribution over episodes
  costliest: [{ episodeId, sessionId, cost, prompts, kind }]  // top 5
}
```

## What this is NOT

- No new evidence methods, no writes.
- No cross-session episode matching (recurring-mistake detection) — that is the
  practice score, and needs episode signatures compared across sessions. Next step.
- No per-episode concordance — derivable later if it earns rent.

## Acceptance criteria
