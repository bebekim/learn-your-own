# 4.7 — Prompt Kind Evidence Backfill

**State:** implemented
**Layer:** 4 (night-shift pipeline queue)
**Dependencies:** Spec 4.5 (evidence, implemented), 4.6 (measurement, implemented).

## Problem

Route C applies to new rows only. Existing ledgers have hundreds of `session_prompts`
rows with a `prompt_kind` but no evidence rows, so the measurement layer (4.6) reports
zero coverage on real data. Waiting for organic accumulation leaves the system
unmeasurable for weeks.

## Design

Replay stored rows through the evidence pipeline, using only data already in the
ledger:

- **Positional**: every index-0 user prompt gets a `positional` evidence row for
  `direction_setting` (log 99).
- **Heuristic**: for rows whose stored `prompt_kind` is a Route-B semantic kind, the
  stored kind IS the historical heuristic output — reuse it. For legacy `user_prompt`
  rows and index-0 `direction_setting` overrides (where the heuristic vote was lost to
  the old hardcoded override), recompute from `prompt_summary` via
  `classifyPromptKind()`.
- **Contextual**: assistant rows carry `response_summary` and `turn_id`. Run
  `classifyResponseContext()` and fan out to all user prompts in the turn, exactly as
  the live Stop path does.

All backfilled rows get `evidence_ref = 'backfill'` so they are distinguishable from
live evidence.

After insertion, `recomputePromptKind` runs for every affected prompt. Kinds may
change (contextual outweighing heuristic — the flips the measurement layer exists to
detect).

### Idempotency

A prompt that already has any evidence rows is skipped entirely. Running the backfill
twice inserts nothing the second time. Live (Route C) rows always have evidence, so
they are never touched.

## Interface

```typescript
export function backfillPromptKindEvidence(kernel: LearningKernel): PromptKindBackfillResult;
```

Result: `{ promptsScanned, promptsSkipped, evidenceInserted, byMethod, promptsRecomputed, kindsChanged }`.

CLI: `lyo backfill-prompt-kind [--db path]`, returning the result as JSON.

## What this is NOT

- **No new signal sources.** Backfill re-derives evidence from stored summaries; it
  does not invent data.
- **No full-text re-classification.** Raw prompt text is unavailable for hashed rows;
  the 240-char summary is the best available input and its heuristic output is marked
  as backfilled.

- [x] Contextual evidence fanned out from stored assistant response summaries
