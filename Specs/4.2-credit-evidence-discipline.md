# Credit evidence discipline (roadmap §6)

Priority: high
State: ready

## Problem

The improvement roadmap's area 6 demanded that transfer credit meet the same
credibility discipline as promotions — "N runs per cell before credit is
recorded" — warning that single-run credit is "precise garbage." The audit
(`issues/done/` review of `docs/superpowers/specs/done/2026-07-27-lyo-improvement-roadmap.md`)
found this was never implemented, and worse, the credit path built later
(`src/lyo/trace-consumer.ts:464-501`) records `helpful`/`harmful` from single
observations per run — the exact N=1 noise §6 condemns. `compareRuns` also
remains a single-pair verdict (`src/runner/compare-runs.ts`).

Posteriors fed by N=1 credit are formally correct and empirically inert:
they sharpen on noise.

## Desired Behavior

Define the **cell** as `(lesson classification, writer model, specId)`.
Credit for a lesson accrues per cell, not per run:

- **harmful**: the cell's failure class recurred in a run where the lesson
  was delivered. Each recurrence is one harmful observation.
- **helpful**: the cell's class was established (≥1 prior recurrence with the
  same spec + model) and did NOT recur in a run where the lesson was delivered.
- A single clean run in a cell is **never** sufficient for helpful; require
  the class to have recurred in ≥2 prior runs of that cell (the same rule as
  the evidence gate's recurrence definition), so helpful means "expected and
  prevented," not "didn't happen to occur."
- `compareRuns` verdicts are used for lesson-level transfer measurement only
  when ≥2 runs exist per cell with matched lineup (same plan + executors);
  single-pair verdicts must be labeled `low_confidence` in output.

## Non-Goals

- No change to the Thompson selection mechanism itself.
- No changes to the sequential-evidence trust gate (that is promotion, not credit).
- No removal of existing credit rows (new discipline applies going forward).

## Edge Cases

- A lesson delivered in a cell with zero prior recurrence history: class
  appearing once is harmful; class absent is **no credit** (not expected yet).
- Runs with different writer models in the same batch: cells must not merge.
- Credit already recorded by the old N=1 path in production lesson files:
  document (don't silently reset) whether counters carry or restart.

## Test Expectations

- harmful on recurrence in a delivered run (existing behavior, retained).
- helpful requires ≥2 prior recurrences in the cell; 1 prior → no credit.
- cells split by model and by specId (same class, different spec → no helpful).
- `compareRuns` returns `confidence: 'low_confidence'` for single-pair,
  `'matched'` when ≥2 runs per side share plan+executors.
- Full suite green.

## Acceptance Criteria

- [ ] compareRuns confidence labeling
- [ ] Decision on legacy counters documented in the commit message

## Known Risks

- Tightening helpful rules will leave most current lessons at low helpful
  counts — posteriors will stay near prior longer. That is the point
  (honesty over false confidence), but delivery rates will visibly drop.
