# At-bat risk inputs, cost blind spots, and file-library quarantine

Priority: medium
State: ready

## Problem

Three audit findings, bundled as one bounded fix batch:

1. **At-bat risk control ignores two of four mandated inputs**
   (`issues/done/candidate-at-bat-prd.md`): `allowedTools` is parsed
   (`src/compiler/candidate-at-bat/task-context.ts:25`) but never consumed,
   and `hasApprovalFriction` is never used by the at-bat scoring layer
   (`scoring.ts:36-43`). The PRD requires allowed tools and approval friction
   to inform risk control.
2. **Cost accounting blind spots** (roadmap §5): the kimi-cli executor
   captures no usage (`src/runner/executors/kimi-cli.ts`); the judge's token
   spend is discarded (`src/lyo/trace-consumer.ts:629-667`); nothing
   aggregates cost per lesson, so "what did a lesson cost to learn" is
   unanswerable.
3. **No quarantine mechanism in the file lesson library** (roadmap §2):
   `isDemoted` is computed on the fly; the lesson file's `- status:` field
   never transitions. Nothing ever quarantines a lesson — unlike the kernel
   SQLite store, which has a real `quarantined` status.

## Desired Behavior

1. `classifyRiskControl` incorporates `allowedTools` (actions outside the
   allowed set count as boundary violations) and `hasApprovalFriction`
   (approval-heavy sessions reduce the risk-control score). `allowedTools`
   defaults stay backward compatible (absent = no constraint). Tests cover
   both inputs plus the at-bat `verifier-first` semantics: the signature must
   require a verifier run before the first edit, not merely `verifierRuns > 0`.
2. kimi-cli executor captures usage when the CLI emits it (stream-json usage
   records) or documents `usage: undefined` explicitly; the judge path in
   trace-consumer records usage per disagreement judged and aggregates it
   into `lyo-update.json` (additive optional `usage` block: judgeTokens,
   judgeCost). Lesson-cost becomes answerable per learn batch.
3. `recordLessonOutcome` transitions the lesson file's `- status:` field:
   `promoted → quarantined` when `harmful >= 2 && helpful == 0` (matching
   `isDemoted`), and quarantined lessons are excluded from `loadLessons`
   (visible via a `includeQuarantined` option for inspection).

## Non-Goals

- No at-bat scoring redesign beyond the two inputs + verifier-first fix.
- No kimi usage fabrication: if the CLI doesn't emit usage, undefined stands.
- No backfill of historical status fields.

## Edge Cases

- `allowedTools: []` means unconstrained (current behavior), not deny-all.
- A lesson already at `harmful=2, helpful=0` gets quarantined on the next
  harmful record, not retroactively.
- Judge usage when OpenRouter omits the usage field: recorded as undefined,
  not zero.

## Test Expectations

- Risk control: out-of-bounds action with allowedTools set → violation;
  approval-friction session → lower risk-control score.
- verifier-first requires verifier run before first edit (new + existing
  tests updated where the old semantics were asserted).
- kimi executor usage documented; judge usage aggregated into lyo-update
  and validated by its schema.
- status transitions promoted→quarantined; quarantined hidden by default,
  visible with option.
- Full suite green.
