# 5.2 — Cost Attribution: turn_id on model_calls

**State:** implemented
**Layer:** 5 (scoring)
**Dependencies:** 5 (scoring layer direction), 4.3 (cost as at-bat risk input).

## Problem

Tokens are the payroll. The Moneyball framing (5) makes cost a first-class dimension:
an out is spend without a state transition, and waste concentrates in retries that
re-send the full context. `model_calls` already carries token counts and
`estimated_cost`, but it links only by `session_id`/`run_id` — there is no way to
answer "what did this turn cost?" without time-proximity guessing.

The join key that exists everywhere else is `turn_id`. `model_calls` lacks it.

## Design

### Schema

Add nullable `turn_id text` to `model_calls`. Existing ledgers have the table without
the column, and `initLedger`'s `create table if not exists` will not alter it — so
`initLedger` gains a minimal additive migration: check `pragma table_info` and
`alter table model_calls add column turn_id text` when missing. This establishes the
pattern for future additive columns (no migration framework; guard with pragma).

### Capture

`RecordModelCallInput` gains optional `turnId`. Capture points pass it when known:

- CLI `model-call record` gains `--turn-id`.
- The run-pipeline recorder keeps passing `runId` only (pipeline runs are not turns).
- Hook-driven capture (adapters emitting usage data with a turn id) is future work;
  the column accepts it when it arrives.

### Measurement

`prompt-kind-report` gains a cost section, per turn and per session:

- spend by turn (sum of `estimated_cost` grouped by `turn_id`)
- session burn: total and per-turn mean
- unattributed spend: calls with null `turn_id` (data-quality signal, like
  `sessionsWithEndedAt`)

Cost per *outcome* (per transition, per on-base, waste ratio) requires the at-bat
outcome join and is explicitly deferred to the at-bat wiring.

## What this is NOT

- No outcome join (needs at-bat score, not yet built).
- No backfill of historical `turn_id` (unknowable for old rows beyond time-proximity
  guessing — not worth it).
- No changes to how `estimated_cost` is computed.

## Acceptance criteria

- [x] `model_calls.turn_id` exists on new and existing ledgers (pragma-guarded alter)
- [x] `recordModelCall` accepts and stores `turnId`
- [x] CLI `--turn-id` flag
- [x] Report shows spend by turn, session burn, unattributed spend
- [x] Full suite passes: `npm test`; `npm run typecheck`
