# 4.6 — Prompt Kind Measurement: Read-Side Over Classification Evidence

**State:** implemented
**Layer:** 4 (night-shift pipeline queue)
**Dependencies:** Spec 4.5 (prompt kind evidence, implemented).

## Problem

Route C (4.5) made classification a belief derived from append-only evidence. But the
system is still Yahoo, not Google: the taxonomy is hand-made, the patterns are
hand-written, and the likelihood ratios (99/3/4) are reasoned, not measured. Worse,
nothing reads the evidence at all (Loop B) — we cannot say whether the evidence system
changes anything, let alone whether its parameters are right.

The Google direction: reliability should be estimated from data, feedback should come
from behavior, and the case for heavier machinery (embeddings) should be empirical.

This spec adds the measurement layer: a read-only report over `session_prompts` and
`prompt_kind_evidence` that quantifies what the classification system is actually doing.
It closes Loop B with a first consumer and produces the numbers that later calibration
(LR refits, EM) and Tier 3 (embeddings) decisions depend on.

## What this is NOT

- **No new evidence methods.** Nothing is written; this is read-side only.
- **No calibration yet.** Pseudo-accuracy is an agreement-structure proxy, not a
  confusion matrix. EM/Dawid-Skene is deferred until volume supports it.
- **No embeddings.** Margin distribution measures the ambiguous residue so the Tier 3
  decision is made with data.

## Metrics (v1)

All computed from `session_prompts`, `prompt_kind_evidence`, and `agent_sessions`.
No new tables, no new columns.

### Coverage

- User prompts with at least one evidence row (should be ~100% post-Route-C).
- User prompts with evidence from more than one method — the calibratable subset.

### Flip rate

A prompt "flipped" when later content evidence (contextual, correction, outcome)
actually caused a change: the stored `prompt_kind` equals a kind the later evidence
voted for, and differs from the `heuristic` vote. Positional dominance (index-0
`direction_setting` outranking the heuristic) is not a flip. Reported overall and by
winning kind. If the flip rate is ~0, Route C is decorative.

### Method concordance

On prompts where multiple content methods voted: for each pair of methods, the
fraction whose evidenced kinds intersect. This measures whether independent signals
agree without reference to the final belief (agreement-with-belief would just restate
the fixed LR ordering). Outcome-linked validation lands with the at-bat score (5).

### Belief margins

For each user prompt with evidence: `top1_logodds - top2_logodds` (prompts with only
one evidenced kind count as max-margin). Reported as a histogram. A large flat-margin
residue is the empirical case for Tier 3 embeddings; a sharp distribution says the
current signals suffice.

### Behavioral proxies

Behavior, not text patterns:

- **Retry**: a user prompt whose token-overlap (Jaccard over `prompt_summary` word
  sets) with the previous user prompt in the same session is ≥ 0.5. A rephrase is
  implicit negative feedback about the preceding turn.
- **Terminal turn / abandonment**: a session whose last prompt is an assistant
  response. Note: `agent_sessions.ended_at` is never written by any code path — the
  report surfaces this as a data-quality finding (`sessionsWithEndedAt`), and the
  terminal-turn proxy is used instead of true abandonment until that loop is closed.

The validation question: do flipped prompts see a different retry rate than unflipped
ones? Reported as retry-rate-by-flip-status.

## Interface

New query module `src/measurement/prompt-kind.ts`:

```typescript
export function buildPromptKindReport(kernel: LearningKernel): PromptKindReport;
```

CLI: new subcommand on the observation group, `prompt-kind-report`, with a presenter
in `src/cli/presenters/` matching the existing report presenters.
