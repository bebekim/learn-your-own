# Close checkBlindness feedback-policy gap and contract small-fixes

Priority: high
State: ready

## Problem

The done/ spec audit found three small but real gaps against the artifact
contract spec (`docs/superpowers/specs/done/2026-07-26-artifact-contract-design.md`):

1. **checkBlindness misses its 4th check.** The spec says
   `feedbackPolicy.codeWriterSees` must be re-stated as a violation "if the
   plan was constructed loosely," but `src/contract/plan.ts:60-103` never
   inspects `feedbackPolicy`. A hand-built plan with
   `codeWriterSees: 'full_report'` passes `checkBlindness` undetected,
   defeating the aggregate-only feedback invariant the architecture rests on.
2. **Test manifest drops `entrypoint`.** The spec says the test manifest is
   "same as code manifest, plus `framework` and `frozen`," but
   `src/contract/test.ts` omits the code manifest's optional `entrypoint`
   field. Zod strips it silently.
3. **Kernel busy-timeout skipped on a false premise.**
   `src/lyo/lesson-store.ts:486-488` claims node:sqlite lacks a busy-timeout
   option, but `src/ledger.ts:21` sets `PRAGMA busy_timeout` in the same repo.
   The implementation plan requires WAL + synchronous NORMAL + 5s busy timeout.

## Desired Behavior

1. `checkBlindness` returns a violation when a plan's `feedbackPolicy.codeWriterSees`
   is not `'aggregate_only'` (loosely-constructed plans, e.g. cast objects).
   The check is covered by a test that builds such a plan object directly
   (bypassing schema validation) and asserts the violation names the policy.
2. `test.ts` accepts optional `entrypoint` like `code.ts`; fixture round-trips it.
3. `lesson-store.ts` sets `PRAGMA busy_timeout = 5000` where WAL is configured,
   and the incorrect comment is corrected.

## Non-Goals

- No new artifact schemas or fields beyond `entrypoint`.
- No changes to runner, consumer, or CLI behavior beyond the checks above.
